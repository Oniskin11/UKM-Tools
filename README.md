# DbRepair

Утилита на Python (CLI + GUI) для обслуживания касс УКМ по SSH/SFTP. Умеет две вещи:

1. **Восстановление БД** кассы через `innodb_force_recovery` (дамп → чистый datadir → восстановление).
2. **Установку модуля ТС ПИоТ**: скачивание `tspiot`, обновление драйвера ККТ и сертификата — с веб-сервера (по HTTP) или из локального каталога (по SFTP) прямо на кассу.
3. **Публикацию дистрибутива** на веб-сервер прямо из GUI: выбираешь ZIP или папку с драйвером ККТ и/или ТС ПИоТ — утилита сама находит файлы, раскладывает их и считает `.sha256`.

Обе задачи работают как по одной кассе, так и по списку касс сразу.

## Быстрый старт

1. Установите зависимости:
   ```powershell
   python -m venv .venv
   .venv\Scripts\Activate.ps1
   pip install .
   ```
2. Создайте конфиг из примера и заполните доступ к кассе:
   ```powershell
   copy config.example.toml config.toml
   ```
   Как минимум задайте `[connection]` (host/username/password). Для ТС ПИоТ — источник в `[distribution]`.
3. Запустите нужное:
   - GUI: `python -m dbrepair.cli --gui --config .\config.toml` (или `dbrepair-gui.exe`);
   - установка ТС ПИоТ на кассу без GUI:
     `python -m dbrepair.cli --tspiot --hosts 192.168.51.101 --config .\config.toml`;
   - восстановление БД на кассу без GUI:
     `python -m dbrepair.cli --config .\config.toml`.

В GUI: впишите адреса касс, при необходимости нажмите «Определить по IP» (для ТС ПИоТ определение и так выполняется автоматически перед установкой) и запустите нужные шаги. Цвет вкладки покажет итог: зелёный — успех, красный — ошибка.

## Возможности

### Восстановление БД
- загружает архив `dbrepair6700+.tgz` на кассу и распаковывает его;
- обновляет `db.ini` (`DBNAME`, `DBPASSWORD`);
- делает резервную копию `/usr/local/mysql/var` в `mysql-db.tgz`;
- включает, а затем отключает `innodb_force_recovery=6` в `/etc/my.cnf`;
- запускает `dbdump.sh` и проверяет `SUCCESS: DB dump complete`;
- сохраняет копию `ukmclient.sql` и на кассе, и локально;
- удаляет `/usr/local/mysql/var`, разворачивает пустой datadir из `mysql5-datadir-empty_46+.tgz`;
- запускает `dbrestore.sh` и проверяет `SUCCESS: DB restore complete`;
- запускает `ukmclient`.

### Установка ТС ПИоТ
- определяет архитектуру кассы (`x64`/`x86`) и каталог (`/usr/local/ukmclient` или `/usr/local/lillo`) автоматически по IP;
- скачивает `tspiot` в целевой каталог, выставляет права и владельца;
- создаёт каталог `data_tspiot`;
- обновляет `libsp-kkt-driver-*.so` нужной разрядности, сохраняя исходные права и владельца;
- кладёт `gismt_cert.txt` в `data_tspiot`;
- **идемпотентно**: перед загрузкой сверяет sha256 (ожидаемый из источника против установленного на кассе) — если совпало, файл не перекачивается;
- умеет перезагружать кассу (по одной и массово).

Источник файлов задаётся в `[distribution]`: либо HTTP-сервер (касса качает сама по curl/wget), либо локальный каталог (утилита заливает файлы на кассу по SFTP). Утилита сама находит последнюю версию.

## Установка

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install .
```

## Настройка

1. Скопируйте `config.example.toml` в `config.toml`.
2. Заполните доступ к кассе, пути к архивам (для восстановления БД) и источник дистрибутивов (для ТС ПИоТ).
3. Если подключаетесь не под `root`, включите `use_sudo = true`.

Полное описание полей — в разделе [Конфигурация](#конфигурация).

## Запуск

### GUI

```powershell
python -m dbrepair.cli --gui --config .\config.toml
```

или собранный `dbrepair-gui.exe`.

В окне сверху — поле файла конфигурации, кнопка «Обзор» и кнопка **«Настройки…»**. Диалог настроек по вкладкам покрывает все секции `config.toml` (Подключение, База данных, Пути, Сервисы, ТС ПИоТ, Источник, Публикация) — можно настроить всё, не редактируя файл вручную. На вкладке «Источник» выбирается HTTP-сервер или локальный каталог. Вкладка **«Публикация драйвера»** в главном окне показывается только когда выбран HTTP-источник.

В окне три вкладки — «Восстановление БД», «Установка ТС ПИоТ» и «Публикация драйвера». В каждой из первых двух:

- список адресов касс (по одному на строку, либо через запятую/точку с запятой);
- отдельная вкладка на каждую кассу с таблицей шагов и журналом;
- статус каждого шага (`Не запускался / Выполняется / Успех / Ошибка`) и комментарий (например, `Уже актуально (v1.0.0.0)`);
- цветной индикатор на вкладке кассы: серый — не запускалось, синий — выполняется, зелёный — успех, красный — ошибка, оранжевый — отменено;
- запуск всех шагов сразу, запуск отдельного шага, отмена, сброс статусов;
- кнопки «запустить/установить на все кассы» и «отменить все».

На вкладке ТС ПИоТ дополнительно: выбор архитектуры и каталога, кнопка «Определить по IP», кнопки перезагрузки кассы и массовой перезагрузки. Определение окружения выполняется автоматически и перед установкой, так что жать «Определить по IP» необязательно.

На вкладке «Публикация файлов»: укажите ZIP-архив или папку от разработчика (кнопки «Обзор файла» / «Обзор папки»), при необходимости поправьте версию и нажмите «Опубликовать на веб-сервер». Утилита ищет драйверы `libsp-kkt-driver-x64.so`/`libsp-kkt-driver-x32.so` и бинарники с именем `tspiot*` в любой раскладке. Архитектура ТС ПИоТ определяется по папке (`x64`, `x86`, `x32`) либо ELF-заголовку файла. Файлы раскладываются в `kkt/<версия>/{x64,x86}/` и `tspiot/<версия>/{x64,x86}/`, для них создаются `.sha256`, назначаются права и обновляются соответствующие `latest.json`. Если номера версии нет в имени источника и не введён вручную, создаётся уникальная UTC-версия по времени публикации. Доступ к веб-серверу берётся из секции `[publish]`.

### CLI — восстановление БД

```powershell
python -m dbrepair.cli --config .\config.toml
```

### CLI — установка ТС ПИоТ

```powershell
# на кассу(ы) из --hosts (по умолчанию берётся connection.host)
python -m dbrepair.cli --tspiot --hosts 192.168.51.101,192.168.51.102 --config .\config.toml
```

После запуска:

- локальная копия `ukmclient.sql` сохраняется в `local_backup_dir/<host>/`;
- лог создаётся в `logs/` с уникальным именем на каждую кассу и запуск.

## Конфигурация

Файл `config.toml` в формате TOML. Секции `[connection]`, `[database]`, `[paths]` нужны для восстановления БД; `[tspiot]` и `[distribution]` — для установки ТС ПИоТ. Ненужную часть можно не заполнять (например, для ТС ПИоТ архивы БД не требуются).

Пути в `[paths]` указываются относительно расположения самого `config.toml`.

### `[connection]` — доступ к кассе по SSH

| Поле | Обязательное | По умолчанию | Описание |
|------|:---:|---|---|
| `host` | да | — | IP/хост кассы. В GUI и CLI (`--hosts`) переопределяется списком касс. |
| `port` | нет | `22` | Порт SSH. |
| `username` | да | — | Пользователь SSH. |
| `password` | нет | — | Пароль SSH. Если не задан и нет `key_filename`, пробуются ключи/агент. |
| `key_filename` | нет | — | Путь к приватному ключу вместо пароля. |
| `timeout` | нет | `20` | Таймаут подключения, сек. |
| `use_sudo` | нет | `false` | `true`, если подключаетесь не под root и нужен `sudo`. |
| `sudo_password` | нет | пароль SSH | Пароль для `sudo`, если отличается. |

### `[database]` — параметры БД (восстановление)

| Поле | Обязательное | Описание |
|------|:---:|---|
| `name` | да | Имя БД, пишется в `db.ini` как `DBNAME`. |
| `password` | да | Пароль БД, пишется в `db.ini` как `DBPASSWORD`. |

### `[paths]` — пути (восстановление БД)

| Поле | По умолчанию | Описание |
|------|---|---|
| `dbrepair_archive` | — (обяз.) | Локальный архив `dbrepair6700+.tgz`. Проверяется при запуске восстановления. |
| `empty_datadir_archive` | — (обяз.) | Локальный архив `mysql5-datadir-empty_46+.tgz`. |
| `local_backup_dir` | — (обяз.) | Локальный каталог для копий `ukmclient.sql`. |
| `remote_tmp_dir` | `/tmp` | Временный каталог на кассе. |
| `remote_dbrepair_dir_name` | из имени архива | Имя распакованного каталога `dbrepair`. |
| `remote_mysql_dir` | `/usr/local/mysql` | Каталог MySQL на кассе. |
| `remote_mysql_var_dir` | `/usr/local/mysql/var` | Каталог данных MySQL. |
| `remote_mysql_backup_name` | `mysql-db.tgz` | Имя резервной копии datadir. |
| `remote_my_cnf` | `/etc/my.cnf` | Путь к `my.cnf`. |
| `remote_dump_filename` | `ukmclient.sql` | Имя файла дампа. |

### `[services]` — команды управления сервисами

| Поле | По умолчанию |
|------|---|
| `mysql_stop` | `/etc/init.d/mysql stop` |
| `mysql_start` | `/etc/init.d/mysql start` |
| `ukmclient_stop` | `/etc/init.d/ukmclient stop` |
| `ukmclient_start` | `/etc/init.d/ukmclient start` |

### `[tspiot]` — установка ТС ПИоТ

| Поле | По умолчанию | Описание |
|------|---|---|
| `target_base` | `/usr/local/ukmclient` | Каталог установки. В GUI переключается на `/usr/local/lillo` и определяется по IP. |
| `data_dir_name` | `data_tspiot` | Имя создаваемого каталога данных. |
| `binary_name` | `tspiot` | Имя исполняемого файла. |
| `gismt_cert_name` | `gismt_cert.txt` | Имя файла сертификата. |
| `owner` | из имени каталога | Владелец файлов (`ukmclient` → `ukmclient:ukmclient`). Задайте явно при необходимости. |

### `[distribution]` — источник дистрибутивов ТС ПИоТ

Задайте один из вариантов. Если указан `local_dir`, он приоритетнее `base_url`.

| Поле | По умолчанию | Описание |
|------|---|---|
| `base_url` | — | Базовый HTTP-адрес репозитория (без авторизации). Касса качает файлы отсюда напрямую по `curl`/`wget`. |
| `local_dir` | — | Путь к локальному каталогу с той же структурой. Утилита заливает файлы на кассу по SFTP. Путь — относительно `config.toml` или абсолютный. |

> Для обратной совместимости поддерживается старая секция `[webserver] base_url` (эквивалент `[distribution] base_url`).

### `[publish]` — доступ к веб-серверу для публикации драйверов

Нужна для вкладки «Публикация драйвера» (заливка новых драйверов ККТ на веб-сервер по SSH/SFTP).

| Поле | Обязательное | По умолчанию | Описание |
|------|:---:|---|---|
| `host` | да | — | Адрес веб-сервера. |
| `username` | да | — | Пользователь SSH (обычно `root`). |
| `password` | нет | — | Пароль SSH. |
| `port` | нет | `22` | Порт SSH. |
| `ukm_dir` | нет | `/var/www/files/UKM` | Корневой каталог репозитория на сервере. |
| `owner` | нет | `www-data:www-data` | Владелец публикуемых файлов. |

Если пароль не хранится в `config.toml`, его можно положить в `.env` рядом с ним: `UKM_PUBLISH_PASSWORD=...`. Файл исключён из Git.

## Источник дистрибутивов ТС ПИоТ

Утилита ожидает такую структуру (одинаковую и для HTTP-сервера, и для локального каталога):

```
UKM/  (корень = base_url или local_dir)
├── tspiot/<версия>/<x64|x86>/tspiot            (+ tspiot.sha256 для HTTP)
├── kkt/<версия>/<x64|x86>/libsp-kkt-driver-*.so (+ .sha256 для HTTP)
└── gismt_cert.txt                               (+ gismt_cert.txt.sha256 для HTTP)
```

- При публикации через GUI создаются `kkt/latest.json` и/или `tspiot/latest.json`: каждый явно указывает версию, которую должны брать кассы. Это позволяет использовать версии разработчика, не упорядочиваемые обычным числовым сравнением (например, `1.0.0.0.512`). На старом сервере без указателя выбирается **последняя** версия по номеру в имени каталога.
- Проверка «изменился ли файл» — по sha256: для HTTP хэш берётся из соседнего `.sha256`, для локального каталога считается на месте.
- Для HTTP «зоны загрузки» (исходные `TS PIoT/esmpack_*` и `Driver KKT *.zip`) раскладываются в этот вид скриптом `ukm-publish.py` на сервере после добавления новой версии.
- Проще всего добавить новый драйвер ККТ через вкладку «Публикация драйвера» в GUI — она сама раскладывает файлы и считает `.sha256` (см. секцию `[publish]`).
- Для локального каталога просто разложите файлы в структуру выше (например, тем же `ukm-publish.py`, запущенным локально).

## Ограничения

- нужен доступ по SSH/SFTP; для системных операций — `root` или рабочий `sudo`;
- скрипты `dbdump.sh` и `dbrestore.sh` должны быть в распакованном каталоге `dbrepair6700+`;
- для сверки хэша на кассе нужен `sha256sum`, `openssl` или `shasum`;
- при HTTP-источнике: на кассе нужен `curl` или `wget`, а сама касса должна иметь сетевой доступ к веб-серверу; при локальном каталоге файлы заливаются по SFTP и такой доступ не требуется.
