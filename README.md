# UKM-Tools

UKM-Tools — графический инструмент и CLI для обслуживания касс UKM по SSH/SFTP. Он рассчитан на работу с одной кассой или списком адресов: для каждой кассы показывает план, статусы шагов и журнал выполнения.

## Возможности

- восстановление базы UKM из дампа;
- пересборка чистой MySQL из штатных архивов UKM с сохранением предыдущего datadir;
- установка или обновление ТС ПИоТ, драйвера ККТ и сертификата ГИС МТ;
- синхронизация времени ККТ;
- публикация дистрибутивов из ZIP-архива или папки разработчика на веб-сервер или в локальный каталог.

## Запуск без Python

Для обычной работы скачайте [DbRepair.exe](release/DbRepair.exe) и положите рядом `config.toml`. Python на компьютере пользователя не нужен. Конфигурацию можно создать копированием [config.example.toml](config.example.toml):

```powershell
Copy-Item config.example.toml config.toml
```

Запустите `DbRepair.exe` двойным щелчком. В верхней части окна можно выбрать другой файл конфигурации или открыть диалог «Настройки…».

## Запуск из исходников

Требуется Python 3.11+.

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install .
Copy-Item config.example.toml config.toml

# GUI
dbrepair-gui --config .\config.toml

# Восстановление БД
dbrepair --config .\config.toml

# Установка ТС ПИоТ на указанные кассы
dbrepair --tspiot --hosts 192.168.51.101,192.168.51.102 --config .\config.toml
```

Для старта достаточно заполнить `[connection]`. Восстановление БД также требует `[database]` и `[paths]`, а установка ТС ПИоТ — `[distribution]`.

## Работа в GUI

| Вкладка | Назначение |
| --- | --- |
| Восстановление БД | Создаёт дамп, разворачивает чистый datadir и восстанавливает UKM. |
| Пересборка MySQL | Получает штатные архивы UKM, сохраняет старый datadir как `var_badN`, разворачивает чистую БД и проверяет схему и запуск `ukmclient`. |
| Установка ТС ПИоТ | Определяет окружение кассы, устанавливает актуальные ТС ПИоТ, драйвер ККТ и сертификат. |
| Синхронизация времени ККТ | Передаёт на ККТ текущее время кассы через штатный канал. |
| Публикация файлов | Разбирает архив или папку от разработчика и публикует актуальные файлы. |

Пересборка и восстановление MySQL меняют данные на кассе. Перед запуском проверьте адрес кассы и наличие нужной резервной копии. Предыдущий каталог данных при пересборке не удаляется, а переименовывается в первый свободный `var_badN`.

## Дистрибутивы ТС ПИоТ

В `[distribution]` укажите один источник:

- `base_url` — HTTP-каталог; касса скачивает файлы сама;
- `local_dir` — локальный каталог; программа передаёт файлы на кассу по SFTP. Он имеет приоритет над `base_url`.

На вкладке «Публикация файлов» выберите ZIP-архив или папку. Программа сама находит `libsp-kkt-driver-*.so`, `tspiot*` и `gismt_cert.txt`, определяет разрядность и раскладывает найденное одинаково для веба и локального источника:

```
UKM/
├── kkt/<версия>/<x64|x86>/libsp-kkt-driver-*.so
├── tspiot/<версия>/<x64|x86>/tspiot
└── gismt_cert.txt
```

Рядом создаются файлы `.sha256`; `kkt/latest.json` и `tspiot/latest.json` указывают актуальные версии. При установке касса получает только изменившиеся файлы.

Для веб-публикации заполните `[publish]`. Пароль можно хранить в `.env` рядом с конфигурацией как `UKM_PUBLISH_PASSWORD`; `.env` исключён из Git. Полный перечень полей и примеры — в [config.example.toml](config.example.toml).

## Разработка

Тесты хранятся в репозитории и проверяют ключевые сценарии публикации и обслуживания касс:

```powershell
pip install pytest
pytest -q
```

Чтобы пересобрать автономный exe:

```powershell
uv run --with pyinstaller pyinstaller --noconfirm --clean --distpath release --workpath build\pyinstaller dbrepair-gui.spec
```

Результат — `release/DbRepair.exe` для Windows x64.
